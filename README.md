# HDR 曝光包围去重影合成台

上传 3～7 张同场景、同尺寸、固定光圈 / ISO / 白平衡的 JPEG 包围曝光照片，
输入每张的快门时间并选定参照帧，服务端自动完成配准、运动去重影与 HDR 合成，
输出成片 PNG 与不确定区域遮罩。

## 功能特性

- **自动配准**：ORB 特征 + RANSAC 估计相似变换，修正手持拍摄造成的轻微平移 / 旋转 / 缩放错位；
  公共重叠区域不足 50% 时拒绝输出成片并报错。
- **HDR 合成**：固定光圈 / ISO / 白平衡下，像素线性亮度 ÷ 快门时间 ≈ 场景辐照度；
  静态区域对未裁切（未过曝 / 未欠曝）的帧加权平均，恢复高光与暗部细节。
- **运动去重影**：对所有帧做两两一致性检验（含"过曝只给出亮度下界、欠曝只给出上界"的边界检验），
  运动区域只保留参照帧内容——**即使参照帧在旧位置过曝、两张非参照帧都在旧位置拍到了同一物体，
  旧物体也不会被当作高光细节留下**；运动物体只保留在参照帧所在位置。
- **抗误判**：纯曝光变化（已按快门归一化）、饱和裁切本身、±1px 级配准残差都不会被当作运动。
- **不确定标记**：全组曝光都缺失细节（如太阳、死黑区域）或无法可靠判断的区域
  （如运动物体附近但参照帧被裁切），保留参照帧内容并在遮罩中标白。
- **结果对比与下载**：页面提供参照帧 ↔ 合成结果滑动对比，可下载成片 PNG 与不确定遮罩 PNG。
- **输入校验**：非法快门（非有限正数）、损坏 / 非 JPEG 图片、尺寸不一致、数量不符均返回明确错误。

## 快速开始（Docker Compose 一键启动）

```bash
docker compose up --build
```

启动后访问：

- **合成台页面**：http://localhost:8000
- **API 文档（Swagger）**：http://localhost:8000/docs
- **健康检查**：http://localhost:8000/api/health

合成结果保存在名为 `results` 的数据卷中（容器内 `/app/results/<job_id>/`），
也可直接通过页面或结果 URL 下载。

## 使用流程

1. 打开 http://localhost:8000 ，点击选择 3～7 张 JPEG（同场景、同尺寸、固定光圈 / ISO / 白平衡）。
2. 为每张图片填写快门时间（秒），支持 `0.004` 或 `1/250` 两种写法。
3. 选择一张作为**参照帧**（运动物体将保留在该帧的位置，建议选中间曝光）。
4. 点击"开始合成"，等待处理完成。
5. 在结果区拖动滑块对比参照帧与合成结果；
   点击按钮下载**成片 PNG** 与**不确定遮罩 PNG**（白色 = 不确定区域）。

## API 说明

### `POST /api/merge`

`multipart/form-data`：

| 字段 | 说明 |
| --- | --- |
| `files` | 3～7 个 JPEG 文件（重复字段） |
| `shutters` | JSON 数组，各帧快门时间（秒，有限正数），如 `[0.002, 0.016, 0.066]` |
| `reference` | 参照帧下标（从 0 开始） |

成功响应 `200`：

```json
{
  "job_id": "6e4b64d9b9d2",
  "result_url": "/api/results/6e4b64d9b9d2/result.png",
  "mask_url": "/api/results/6e4b64d9b9d2/mask.png",
  "reference_url": "/api/results/6e4b64d9b9d2/reference.png",
  "stats": {
    "frames": 3, "reference": 2, "width": 640, "height": 480,
    "downscaled": false, "overlap_pct": 98.8,
    "motion_pct": 8.39, "uncertain_pct": 2.16,
    "align_inliers": [117, 208, -1]
  }
}
```

### `GET /api/results/{job_id}/{name}`

`name` 为 `result.png`（成片）、`mask.png`（不确定遮罩，白 = 不确定）、
`reference.png`（参照帧）、`meta.json`（统计信息）。

### 错误响应（HTTP 400）

| 场景 | 示例信息 |
| --- | --- |
| 数量不符 | `需要上传 3～7 张 JPEG 图片，当前为 2 张` |
| 非法快门 | `非法快门时间 -0.016：必须为有限正数（单位：秒）` |
| 非 JPEG | `第 2 张不是 JPEG 图片` |
| 图片损坏 | `第 2 张图片损坏，无法解码` |
| 尺寸不一致 | `图片尺寸不一致：所有图片必须具有相同的宽和高` |
| 配准失败 | `第 2 张与参照帧的匹配点不足，无法配准` |
| 重叠不足 | `配准后公共重叠区域仅 30%（低于 50%），不输出成片` |

## 算法原理

1. **配准**：降采样灰度图上提取 ORB 特征，与参照帧做比率检验匹配，
   RANSAC 估计相似变换（平移 / 旋转 / 缩放）后重投影到参照帧坐标系；
  统计所有帧的公共覆盖区域占比，不足 50% 拒绝输出。
2. **曝光归一化**：以 gamma 2.2 近似 JPEG 响应曲线做线性化，
   线性亮度 ÷ 快门时间得到辐照度估计（固定光圈 / ISO / 白平衡前提下各帧可比）。
3. **运动检测**：对每两帧做一致性检验——
   - 两帧均有效：辐照度差异超过相对容差（比较时对邻域 ±1px 取 min/max，容忍配准残差）；
   - 一帧高光裁切：裁切只说明辐照度 ≥ 下界，若另一帧显著低于该下界，则场景必然变化；
   - 一帧暗部不可靠：同理，若另一帧显著高于该上界，则场景必然变化。
   
   因此"参照帧过曝 + 非参照帧在旧位置拍到物体"会被判为运动而非高光细节；
   检验结果经形态学清理与小连通块过滤得到运动掩码。
4. **合成**：静态区域对所有未裁切帧按三角帽权重加权平均；
   运动区域只取参照帧（参照帧有效时即为确定结果）。
5. **不确定区域**：没有任何有效曝光的像素（全组过曝 / 全组欠曝 / 运动区域中参照帧被裁切）
   保留参照帧内容，并在遮罩中标记。
6. **色调映射**：Reinhard 算子按亮度压缩 HDR，输出 8bit PNG。

## 注意事项与限制

- 输入要求同场景、同尺寸、固定光圈 / ISO / 白平衡的 JPEG；快门时间需手动准确填写。
- 超过 1200 万像素的图片会等比缩小后处理（控制内存与耗时），`stats.downscaled` 会标记。
- 单张图片上限 40MB；配准基于静态场景特征，场景纹理过少时可能配准失败。
- 结果保存在容器卷中，重启容器不丢失（删除卷则清空）；历史结果需自行清理。
